# 合同中心（e签宝）前端对接文档

> ⚠️ **2026-10-29 起：列表接口以 [合同中心_列表接口对接文档_20261029.md](./合同中心_列表接口对接文档_20261029.md) 为准**
> （新增客户字段 `accountId/accountCode/accountName`、院部名称 `wiseDepartName`、院部筛选 `wiseDepartId`；
> `keyword` 收窄为仅客户编码/客户名称，文书ID/文书名称/合同号改为独立参数 `documentId`/`documentName`/`contractId`；
> 院部下拉复用现有公共接口）。
> 本文档的详情 / 下载 / 认证状态部分仍然有效。

> 文档性质：前端对接指南（可直接用于 AI 生成页面/请求代码）
> 编写日期：2026-10-19
> 后端实现：`HospitalElectronicContractController#centerList / centerDetail / centerDownload`
> 数据来源：`hospital_electronic_contract`（主表）、`hospital_contract_signer`（签署人）、`hospital_contract_attachment`（附件）

---

## 0. 一句话说明

合同中心是 e签宝 的**自建合同列表**（E签宝 没有原生合同列表），只展示 **e签宝（`manufacturer=2`）** 合同，**包含已作废**
，按登录用户院部隔离。

共 3 个接口：**列表 / 详情 / 下载**。

## 1. 通用约定

### 1.1 基路径

```
/medical/contract/center
```

### 1.2 请求头

沿用项目现有鉴权头（与其他 medical 接口一致）：

```
Content-Type: application/json
X-Access-Token: <token>
X-Biz-Line: hospital
X-Sign / X-Nonce-Str / X-Timestamp: <网关签名>
```

> 前端使用现有请求封装即可，无需额外处理。

### 1.3 统一响应结构

```json
{
  "success": true,
  "message": "",
  "code": 200,
  "result": {}
}
```

- 业务失败时 `success=false`，`message` 为提示文案；
- 下列接口只描述 `result` 部分。

> ⚠️ **下载接口是例外（实测确认）**：`/center/download` 的 `result` 是**字符串**，后端走的是
> `Result.ok(String)` 重载（`Result` 同时存在 `ok(Object)` / `ok(String)` / `ok()` 三个重载），
> 因此 **`message` 也会被置成同一个 URL**。
> **前端请只读 `result`**，不要用 `message` 判断成败，也不要把 `message` 当提示文案展示。

### 1.4 日期格式

所有时间字段均为字符串：**`yyyy-MM-dd HH:mm:ss`**（东八区），可能为 `null`。

## 2. 接口一：合同列表（分页）

```
GET /medical/contract/center/list
```

### 2.1 请求参数（Query）

| 参数                | 类型      | 必填 | 默认 | 说明                                           |
|-------------------|---------|----|----|----------------------------------------------|
| `pageNo`          | Integer | 否  | 1  | 页码，从 1 开始                                    |
| `pageSize`        | Integer | 否  | 10 | 每页条数                                         |
| `createTimeBegin` | String  | 否  | —  | 合同创建时间起，`yyyy-MM-dd` 或 `yyyy-MM-dd HH:mm:ss` |
| `createTimeEnd`   | String  | 否  | —  | 合同创建时间止；**只传日期时后端自动补到当天 23:59:59**           |
| `contractStatus`  | String  | 否  | —  | 签署状态，**多选逗号分隔**，传原始枚举，如 `SIGNING,COMPLETE`   |
| `keyword`         | String  | 否  | —  | 关键字：**合同id / 文书名称（业务类型名称）/ 附件标题**（模糊）        |

> **院部隔离由后端自动完成**（取当前登录用户院部），前端**不要**传院部参数。
> `keyword` 为纯数字时，会同时匹配「文书id」和「合同号」。

### 2.2 响应

`result` 为分页对象：

```json
{
  "records": [
    ContractItem
  ],
  "total": 128,
  "size": 10,
  "current": 1,
  "pages": 13
}
```

#### ContractItem 字段

| 字段                   | 类型                  | 说明                                                                                                           |
|----------------------|---------------------|--------------------------------------------------------------------------------------------------------------|
| `id`                 | Integer             | **文书id**（列表主键，详情/下载都用它）                                                                                      |
| `contractId`         | String              | 合同号（可能为 null）                                                                                                |
| `documentName`       | String              | **文书名称（合同级）**：取业务类型名称，如「术前签署」「术中签署」「非常规手术告知书」；**同一 `businessType` 恒为同一名称**（附件标题是文档级，见 `attachments[].title`） |
| `contractStatus`     | String              | 签署状态**原始枚举**（见 §5）                                                                                           |
| `contractStatusDesc` | String              | 签署状态中文（后端已映射，前端可直接展示）                                                                                        |
| `createTime`         | String              | 合同创建时间                                                                                                       |
| `completeTime`       | String              | 完成时间（可能为 null）                                                                                               |
| `manufacturer`       | Integer             | 厂商：`1` 契约锁，`2` E签宝（本列表固定为 2）                                                                                 |
| `manufacturerDesc`   | String              | 厂商描述                                                                                                         |
| `businessType`       | Integer             | 业务类型（见 §6）                                                                                                   |
| `businessTypeDesc`   | String              | 业务类型名称                                                                                                       |
| `wiseDepartId`       | String              | 院部ID（可能为 null）                                                                                               |
| `isDeleted`          | Integer             | `0` 正常，`1` 已作废                                                                                               |
| `signers`            | Array\<Signer\>     | 签署方列表                                                                                                        |
| `attachments`        | Array\<Attachment\> | 附件列表（可能为空，见 §7）                                                                                              |

#### Signer

| 字段               | 类型      | 说明                                                    |
|------------------|---------|-------------------------------------------------------|
| `signUserId`     | String  | 签署人ID（027 员工 / 002 客户）                                |
| `signUserName`   | String  | 签署人姓名                                                 |
| `signStatus`     | String  | 签署状态原始枚举（见 §5）                                        |
| `signStatusDesc` | String  | 签署状态中文                                                |
| `signTime`       | String  | 签署时间（未签为 null）                                        |
| `serialNo`       | Integer | 签署顺序（1 开始）                                            |
| `authStatus`     | Integer | **认证状态**：0 未认证 / 1 已认证 / 2 认证过期（见 §5.1）；契约锁合同为 `null` |
| `authStatusDesc` | String  | 认证状态中文（后端已映射，可直接展示）                                   |
| `authTime`       | String  | **认证完成时间** `yyyy-MM-dd HH:mm:ss`；未认证为 `null`          |
| `authExpireTime` | String  | **认证有效期截止时间**（核身流程 7 天有效）；未认证为 `null`                 |

> ⚠️ **认证字段只在详情接口 `/center/detail` 返回**，且为**请求时刻的实时查询结果**（读身份认证表，非合同快照）。
> 列表接口 `/center/list` **不返回**这 4 个字段（避免按签署方数量放大查询）。

#### Attachment

| 字段                 | 类型      | 说明                                             |
|--------------------|---------|------------------------------------------------|
| `id`               | Integer | 附件ID                                           |
| `title`            | String  | 附件名称                                           |
| `pdfUrl`           | String  | **PDF 下载地址**（可能为 null）                         |
| `imageUrl`         | String  | 预览图地址                                          |
| `fileType`         | Integer | 文件类型（17 非常规 / 13 术前讨论 / 14 术中物品 / 12 达人押金）     |
| `fileTypeName`     | String  | 文件类型名称                                         |
| `fileItemType`     | Integer | 子类型（1801 主文档 / 1802 作废声明 / 1301 / 1401 / 1201） |
| `fileItemTypeName` | String  | 子类型名称                                          |

## 4. 接口三：文书下载

```
GET /medical/contract/center/download?id={文书id}
```

### 4.1 请求参数

| 参数   | 类型      | 必填    | 说明   |
|------|---------|-------|------|
| `id` | Integer | **是** | 文书id |

### 4.2 响应

`result` 为 **PDF 地址字符串**，可能为 `null`。

```json
{
  "success": true,
  "code": 200,
  "result": "https://qiniu-test.zhifa.cn/uploads/qys/2026-10-19/xxx.pdf"
}
```

取不到时：

```json
{
  "success": true,
  "code": 200,
  "result": null
}
```

### 4.3 取数逻辑（后端）

1. **优先**：`hospital_contract_attachment` 中已落库的**主文档**附件 `pdfUrl`；
2. **回退**：签署中附件尚未落库时，返回合同**当前 PDF**（`contract_details.pdfKey` + 七牛域名）。

> ⚠️ 回退返回的是「当前最新版本 PDF」（签署到第几人就是第几人签完的版本），不是最终定稿；全部签完后通常走第 1 条。

### 4.4 前端用法

```js
const res = await request.get('/medical/contract/center/download', {params: {id}});
const url = res.result;
if (!url) {
    message.warning('暂无可下载的文书');
    return;
}
// 方式一：新窗口预览/下载
window.open(url);
// 方式二：触发下载（同源或已配置 CORS 时）
const a = document.createElement('a');
a.href = url;
a.target = '_blank';
a.download = '';
a.click();
```

## 5. 状态枚举对照（`contractStatus` / `signStatus`）

后端同时返回原始值和中文描述（`*Desc`），**前端可直接展示 `*Desc`**，筛选框提交**原始值**。

| 原始枚举          | `*Desc`（后端返回，可直接展示） |
|---------------|---------------------|
| `DRAFT`       | 草稿                  |
| `WAITING`     | **待签署**             |
| `SIGNING`     | **签署中**             |
| `SIGNED`      | 已签署                 |
| `COMPLETE`    | **已完成**             |
| `RECALLED`    | 已撤回                 |
| `REJECTED`    | 已退回                 |
| `EXPIRED`     | 已截止签署               |
| `FILLING`     | 拟定中                 |
| `INVALIDING`  | 作废中                 |
| `INVALIDED`   | **已作废**             |
| `TERMINATING` | 作废中                 |
| `TERMINATED`  | **已作废**             |

**筛选下拉建议值**：`SIGNING`（签署中）、`COMPLETE`（已完成）、`INVALIDED`（已作废）。

> 注意：`isDeleted=1` 表示合同已作废（主表软删），可作为「已作废」的补充判断，但不是唯一依据（`contractStatus` 更准确）。

---

### 5.1 认证状态（`authStatus`，仅详情接口返回）

| 值   | `authStatusDesc` | 含义                        | 前端展示建议         |
|-----|------------------|---------------------------|----------------|
| `0` | 未认证              | 该签署方无认证记录 / 尚未完成实名认证      | 灰色标签「未认证」      |
| `1` | 已认证              | 已完成认证且在有效期内               | 绿色标签「已认证」      |
| `2` | 认证过期             | 认证已过有效期（核身流程 7 天有效），需重新认证 | 橙色/红色标签「认证已过期」 |

- `authTime`：认证**完成**时间（未认证为 `null`）；
- `authExpireTime`：认证**有效期截止**时间（未认证为 `null`）；
- 状态来源为**本地身份认证表**（请求时实时读取，并按 flowId/有效期兜底计算），**不逐签署方调用 e签宝 接口**——
  因此反映的是「已落库的最新认证状态」；若认证回调尚未送达，可能短暂滞后，刷新详情即可。
- **契约锁合同（`manufacturer=1`）这 4 个字段恒为 `null`**，前端按「不展示」处理；
- 后端单条查询失败时只记日志，该签署方的认证字段为 `null`，不影响详情其它数据。

## 7. 注意事项（前端必读）

1. **只含 e签宝 合同**：契约锁合同不在本列表；
2. **包含已作废**：不过滤软删，用 `isDeleted` / `contractStatus` 区分；
3. **按院部隔离**：后端自动取登录用户院部；无院部绑定的账号（总部）可看全部；
4. **附件可能为空**：签署中的合同（尤其非常规）附件尚未落库，此时：
    - `attachments` 为空数组；
    - **下载请统一调用 `/center/download`**，不要只依赖 `attachments[].pdfUrl`；
5. **文书名称**：`documentName` 是**合同级名称**（= 业务类型名称），同一 `businessType` 永远同一个名字；
   术前签署/术中签署这类合同内含多份文档，各文档名字在 `attachments[].title` 里，**不要用附件标题当列表标题**；
6. **分页**：`total` / `pages` 直接用于分页组件；
7. **详情/下载的 `id` 是列表的 `id`**（文书id），不是 `contractId`。

## 8. 典型页面流程

```
进入合同中心
  └─ GET /center/list?pageNo=1&pageSize=10
       ├─ 筛选（时间/状态/关键字）→ 带参重新请求第 1 页
       ├─ 点击「查看详情」→ GET /center/detail?id=xxx
       └─ 点击「文书下载」→ GET /center/download?id=xxx
                              ├─ 有 url → window.open(url)
```

| **认证查询容错**             | `detail_authQueryFailure_doesNotBreakDetail`    | ✅ 单条查询异常只告警，详情与签署状态照常返回                                                                                                 |

### 10.4 覆盖边界（重要）

|           | 内容                                                                                                   |
|-----------|------------------------------------------------------------------------------------------------------|
| ✅ **已覆盖** | Controller 路由映射、请求参数透传、统一响应结构、VO 字段与嵌套集合的 JSON 序列化、分页字段；**签署方认证状态的填充逻辑**（e签宝 填充 / 契约锁 跳过 / 单条查询失败容错） |
| ❌ **未覆盖** | Service 层真实查询逻辑：**只查 e签宝合同 / 包含已作废 / 按院部隔离 / 附件取数优先级（已落库附件 → 当前 PDF）** —— 需 Spring 上下文 + 测试库，属集成测试范畴 |

> 因此本文档的字段与结构可直接采信；**业务筛选/隔离行为**需另做集成测试或在测试环境联调验证。

### 10.5 复跑方式

```bash
# 必须用 JDK 8：项目依赖 sun.misc.BASE64Encoder，JDK 9+ 编译失败
export JAVA_HOME=<你的 JDK 8 Home>

mvn -pl jeecg-module-medical-start -am \
  -Dtest=HospitalElectronicContractControllerTest -DfailIfNoTests=false test
```

> 坑：`/usr/libexec/java_home -v 1.8` 在 macOS 上可能选中 **JavaAppletPlugin 的 JRE**（无 `lib/tools.jar`），
> 导致 `Could not find artifact com.sun:tools:jar:1.8.0`。请显式指定
`/Library/Java/JavaVirtualMachines/jdk1.8.0_xxx.jdk/Contents/Home`。
